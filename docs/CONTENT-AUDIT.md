## 2. 抓取设计：合理之处（证据）

- **分源排名不混口径**：主榜 `#1–#9`、py/ts 子榜从 `#10` 起并在描述标注；`rank_by_source` 分开存。
- **同天幂等**：18:00 重复触发时检测「笔记存在 + validate PASS + HEAD=远端 + 线上 200」，只验证不重抓。
- **validate 是硬门**：格式/唯一性/四行齐全/主榜≥5/MOC 计数/meta 文件/相似度≥0.85 硬拦/「最高日增」与 metrics 对账。
- **数值单一事实源**：`meta`（license/官网/创建/fork/archived）+ `metrics`（增量/相对增幅/归属）+ `stats`（第 N 次）。
  抽查 10-18 前三名，license、创建时间、最近 push 与 GitHub API 完全一致。
- **内容级新鲜度校验**：部署后要求新数值命中、旧数值 0 命中，而不是只看 200。
- **坑文档化**：sponsor 卡片过滤、壳页重试、双源不一致不混用、ossinsight 覆盖 0.3%、超时铁律（历史挂死 93 分钟）。

## 5. 内容质量：两个结构性错位

1. **对作者说话 vs 对读者说话**：正文大量出现 `~/.agents/skills/`、`你的情报脚本` 等第二人称，公开读者无法代入。
2. **内容富、站点只用一小段**：旧索引 778 条里仅 236 条 description 带榜位/来源、195 条 searchText 含星数/日增；
   每条正文平均 452 字，但索引截到 600 字符，大量「对你的价值」细节不在检索范围。
3. **早期内容偏薄**：5–6 月约 10 仓/5.5K 字，且分级/事实密度未达现行规则；站点与近期内容同等对待。
4. **长文缺摘要**：单篇 20+ 仓、250 行，读者没有 30 秒入口。
